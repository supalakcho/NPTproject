**ปรับปรุงล่าสุด:** 8 ตุลาคม 2026
**อ้างอิง:** requirement ต้นฉบับ (Phase 0) + ข้อตกลงเพิ่มเติมระหว่างออกแบบ Database (Phase 1)
**สถานะ:** Database Design เสร็จแล้ว (ไฟล์ `notebook_loan.sql`) · ขั้นถัดไปคือ Phase 2 Design API

> สัญลักษณ์ในเอกสาร: **[ยืนยันแล้ว]** = User ตอบแล้ว · **[สมมติฐาน]** = ผู้ออกแบบกำหนดไว้ แก้ได้ · **[เปลี่ยนจากต้นฉบับ]** = ต่างจาก requirement เดิม

## 1. ภาพรวมระบบ

ระบบสำหรับจัดการการยืม-คืนโน๊ตบุ๊คให้สมาชิก เป้าหมายหลักคือแก้ปัญหาการยืมเกินเวลา ให้ใช้งานง่ายสำหรับผู้ใช้ที่ไม่เก่งเทคโนโลยี รองรับมือถือ และโหลดเร็ว ดีไซน์โทนคม ชัด น่าเชื่อถือ

| หัวข้อ | รายละเอียด |
| --- | --- |
| ผู้ใช้หลัก | แอดมิน (Admin), สมาชิก (Member) |
| Frontend | JavaScript (ไม่ใช้ library หนัก) |
| Backend | Node.js / Express |
| Database | MariaDB 10.4+ (XAMPP) หรือ MySQL 8.0.16+ |
| Hosting | XAMPP / Localhost |
| ภาษา | ภาษาไทย |

## 2. ข้อตกลงที่เปลี่ยนจาก requirement ต้นฉบับ

| เรื่อง | ต้นฉบับ | ล่าสุด |
| --- | --- | --- |
| การยืม | แอดมินอนุมัติ/ยกเลิกการยืม | สมาชิกกดยืมได้ทันทีถ้าเครื่องว่าง ไม่ต้องรออนุมัติ แอดมินยกเลิกได้ |
| การคืน | สมาชิกคืนโน๊ตบุ๊ค | คืน 2 ขั้น: สมาชิกกดคืน → แอดมินยืนยันรับเครื่องและตรวจสภาพ |
| การแจ้งเตือน | อีเมล (Should Have) | แจ้งเตือนในระบบอย่างเดียว ตัดอีเมลออก |
| สถานะโน๊ตบุ๊ค | เก็บ ว่าง/ยืม/จอง/เสียหาย | เก็บเฉพาะสภาพเครื่อง ส่วน ว่าง/ยืม/จอง ระบบคำนวณเองจากข้อมูลการยืมและการจอง |
| ใหม่ | – | ต่อเวลายืมได้ |
| ใหม่ | – | บันทึกการคืนช้า (ไม่มีบทลงโทษ) |

## 3. User Roles & Permissions

ใช้ระบบสิทธิ์แบบ RBAC (role → permission) เพิ่ม role ใหม่ในอนาคตได้โดยไม่ต้องแก้โครงสร้าง ผู้ใช้ 1 คนมี 1 role **[สมมติฐาน]**

**สมาชิก**

- สมัครสมาชิกได้เองและใช้งานได้ทันที ไม่ต้องให้แอดมินอนุมัติ **[สมมติฐาน]**
- ค้นหาและดูรายการโน๊ตบุ๊คพร้อมสถานะ
- ยืมโน๊ตบุ๊คทันที **[ยืนยันแล้ว]**
- จองล่วงหน้า และยกเลิกการจองของตัวเอง
- กดคืนโน๊ตบุ๊ค **[ยืนยันแล้ว]**
- ต่อเวลายืม **[ยืนยันแล้ว]**
- ดูประวัติการยืม/จองของตัวเองเท่านั้น
- ดูแจ้งเตือนของตัวเอง
- แก้ไขโปรไฟล์ของตัวเอง

**แอดมิน**

- จัดการโน๊ตบุ๊ค ยี่ห้อ รุ่นและสเปก (เพิ่ม แก้ไข ลบ)
- ยืนยันรับเครื่องคืนและบันทึกสภาพเครื่อง **[ยืนยันแล้ว]**
- ยกเลิกรายการยืมและการจองของทุกคน
- ดูประวัติการยืม-คืนและการจองของสมาชิกทุกคน
- ดู แก้ไข และระงับบัญชีสมาชิก
- ดูรายงาน
- แก้ไขค่าตั้งค่าระบบ (เช่น ชั่วโมงยืมสูงสุด เวลาแจ้งเตือน)
- ดู Audit Log

## 4. Main Workflows

### สมาชิก – ยืมทันที

1. Login
2. ค้นหาโน๊ตบุ๊คที่สถานะ "ว่าง"
3. กดยืม เลือกเวลาคืน (ไม่เกิน 24 ชม.) ระบบตรวจว่าเครื่องว่างและไม่ทับช่วงที่คนอื่นจองไว้
4. รับเครื่องและใช้งาน
5. ได้รับแจ้งเตือนในระบบก่อนครบกำหนดคืน 60 นาที
6. (ถ้าต้องการ) กดต่อเวลา
7. นำเครื่องมาคืนและกดคืนในระบบ
8. แอดมินยืนยันรับเครื่อง เครื่องกลับเป็น "ว่าง"

### สมาชิก – จองล่วงหน้า

1. Login แล้วเลือกเครื่องและช่วงเวลา (เริ่ม–สิ้นสุด)
2. ระบบตรวจว่าช่วงเวลาไม่ทับการจองหรือการยืมอื่น
3. มารับเครื่องในช่วงที่จอง ภายใน 30 นาทีหลังเวลาเริ่ม (ถ้าไม่มา การจองหมดอายุอัตโนมัติ)
4. เมื่อรับเครื่อง การจองกลายเป็นรายการยืม แล้วเข้าสู่ขั้นตอนเดียวกับการยืมทันที

### แอดมิน

1. Login
2. จัดการข้อมูลโน๊ตบุ๊คและสมาชิก
3. ดูรายการ "รอยืนยันรับคืน" → ตรวจสภาพเครื่อง → ยืนยันรับคืน (ถ้าเสียหาย ระบบเปลี่ยนสภาพเครื่องเป็น "เสียหาย")
4. ตรวจสอบประวัติการยืม-คืน และยกเลิกรายการที่ผิดปกติ
5. ดูรายงาน

## 5. Business Rules

### การยืม

- ยืมได้เฉพาะเครื่องที่สภาพปกติและไม่ได้ถูกยืมอยู่
- ยืมได้ไม่เกิน 24 ชั่วโมง
- สมาชิก 1 คนยืมพร้อมกันได้ 1 เครื่อง **[สมมติฐาน]**
- การยืมทันทีต้องไม่ทับช่วงเวลาที่คนอื่นจองไว้
- เครื่องเดียวยืมซ้อนกัน 2 รายการไม่ได้ (บังคับในระดับฐานข้อมูล)

### การต่อเวลา **[ยืนยันแล้ว]**

- สมาชิกต่อเวลาได้เองโดยไม่ต้องให้แอดมินอนุมัติ
- ต่อได้เมื่อยังไม่กดคืน ยังไม่เกินกำหนด และไม่มีคนจองเครื่องต่อในช่วงที่ขอต่อ
- รวมเวลายืมทั้งหมดต้องไม่เกิน 24 ชั่วโมงนับจากเวลาที่ยืม
- ระบบบันทึกกำหนดคืนเดิมและกำหนดคืนใหม่ไว้ใน Audit Log

### การจองล่วงหน้า **[ยืนยันแล้ว]**

- จองเป็นช่วงเวลา (เริ่ม–สิ้นสุด) ล่วงหน้าได้ไม่เกิน 7 วัน
- ช่วงจองยาวไม่เกิน 24 ชั่วโมง
- ช่วงจองต้องไม่ทับการจองหรือการยืมอื่นของเครื่องเดียวกัน
- ไม่มารับเครื่องภายใน 30 นาทีหลังเวลาเริ่ม การจองหมดอายุ **[สมมติฐาน]**
- สมาชิกยกเลิกการจองของตัวเองได้ แอดมินยกเลิกได้ทุกรายการ

### การคืน **[ยืนยันแล้ว]**

- สมาชิกกดคืน → สถานะเป็น "รอยืนยันรับคืน"
- แอดมินยืนยันรับเครื่อง พร้อมระบุสภาพ (ปกติ / เสียหาย) → เครื่องกลับเป็น "ว่าง" หรือ "เสียหาย"
- เครื่องยังไม่ว่างจนกว่าแอดมินจะยืนยัน
- กรณีสมาชิกลืมกด แอดมินบันทึกรับคืนได้โดยตรง

### การคืนช้า **[ยืนยันแล้ว]**

- ไม่มีบทลงโทษ (ไม่ระงับสิทธิ์ ไม่มีค่าปรับ)
- ระบบแจ้งเตือนเมื่อเกินกำหนด และบันทึกว่าคืนช้า
- ตัดสินว่าคืนช้าจากเวลาที่สมาชิกกดคืน (ไม่ใช่เวลาที่แอดมินยืนยัน)

### การแจ้งเตือน **[ยืนยันแล้ว]**

- แจ้งเตือนในระบบอย่างเดียว
- ประเภท: ใกล้ครบกำหนดคืน (ก่อน 60 นาที), เกินกำหนดคืน, ใกล้ถึงเวลาจอง, รายการยืมถูกยกเลิก, การจองถูกยกเลิก
- หลังต่อเวลา ระบบแจ้งเตือนใกล้ครบกำหนดใหม่ตามกำหนดคืนใหม่

### ทั่วไป

- สมาชิกเห็นเฉพาะข้อมูลของตัวเอง
- แอดมินจัดการข้อมูลสมาชิกและโน๊ตบุ๊คได้เต็มรูปแบบ
- การลบข้อมูลหลัก (ผู้ใช้ ยี่ห้อ รุ่น เครื่อง) เป็น Soft Delete
- ห้ามลบเครื่องที่มีการยืมค้างหรือการจองในอนาคต
- รายการยืมและการจองไม่ลบ ใช้ "ยกเลิก" แทน

### ค่าที่แอดมินปรับได้ (ตาราง settings)

| ค่า | ค่าเริ่มต้น |
| --- | --- |
| ชั่วโมงยืมสูงสุด (รวมต่อเวลา) | 24 ชม. (ห้ามเกิน 24) |
| จองล่วงหน้าได้ไม่เกิน | 7 วัน |
| เวลาผ่อนผันรับเครื่องที่จอง | 30 นาที |
| แจ้งเตือนก่อนครบกำหนดคืน | 60 นาที |
| ยืมพร้อมกันได้สูงสุดต่อคน | 1 เครื่อง |

## 6. สถานะในระบบ

**สถานะโน๊ตบุ๊ค:** ว่าง · ถูกยืม · ถูกจอง · เสียหาย · ซ่อมบำรุง · ปลดระวาง

**สถานะการยืม:** กำลังยืม · เกินกำหนด · รอยืนยันรับคืน · คืนแล้ว · ยกเลิก (+ ป้าย "คืนช้า")

**สถานะการจอง:** รอใช้ · ถึงเวลาใช้ · รับเครื่องแล้ว · หมดอายุ (ไม่มารับ) · ยกเลิก

## 10. ข้อกำหนดด้านเทคนิคและความปลอดภัย

- Password hash ด้วย bcrypt ห้ามเก็บ plain text
- Prepared Statement ทุก query
- Validate และ sanitize input ทุกครั้ง
- ตรวจสิทธิ์ทุก API และตรวจ ownership (สมาชิกเข้าถึงได้เฉพาะข้อมูลตัวเอง)
- ใช้ JWT แบบ stateless และมีวันหมดอายุ **[สมมติฐาน]**
- ไม่ส่ง error stack trace ให้ผู้ใช้
- การยืม การจอง และการต่อเวลาทำใน transaction และล็อกแถวเครื่องก่อนตรวจ เพื่อกันคำขอพร้อมกัน
- กฎที่ขึ้นกับเวลาปัจจุบันตรวจที่ backend (ฐานข้อมูลตรวจกฎที่ไม่ขึ้นกับเวลาปัจจุบัน)
- เวลาทั้งหมดเป็นเวลาไทย (UTC+7) ตั้ง `timezone: '+07:00'` ที่ connection ของ Node.js
- Scheduled job (เช่น node-cron) ทุก 5 นาที สำหรับสร้างแจ้งเตือน

**Logging**

- เก็บในฐานข้อมูล (audit_logs): Login สำเร็จ/ไม่สำเร็จ, Logout, Register, Create/Update/Delete, Permission Denied
- เขียนลงไฟล์: Validation Failed, Server Error, Database Error, API Request สำคัญ
