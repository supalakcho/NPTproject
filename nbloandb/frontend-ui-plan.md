# แผนออกแบบ Frontend – ระบบยืมคืนโน๊ตบุ๊ค

**อ้างอิง:** requirement-summary.md (ปรับปรุงล่าสุด 8 ตุลาคม 2026)
**ขอบเขต:** Frontend เท่านั้น
**สถานะ:** ร่างแผน รอตรวจทานก่อนเริ่มเขียนโค้ด

> ตอนนี้ Phase 2 (Design API) ยังไม่เสร็จ แผนนี้จึงออกแบบให้ frontend เรียกข้อมูลผ่าน **API adapter** ตัวเดียว ช่วงแรกต่อกับ mock data ไปก่อน ทำให้พัฒนาและทดสอบ UI ได้ทันที เมื่อ API จริงเสร็จก็สลับ adapter โดยไม่ต้องแก้หน้าจอ

## 1. แนวทางเทคนิค

- ใช้ Vanilla JavaScript (ES Modules) ไม่ใช้ framework ตามข้อกำหนด "ไม่ใช้ library หนัก"
- ทำเป็น SPA แบบ hash router (`#/loans`, `#/admin/returns`) รันบน XAMPP ได้โดยไม่ต้องตั้งค่า server rewrite

### โครงสร้างไฟล์

```
frontend/
  index.html
  css/
    tokens.css        // สี ฟอนต์ ระยะห่าง
    base.css
    components.css
  js/
    main.js           // จุดเริ่มต้น
    router.js         // hash router + ตรวจ role ก่อนเข้าหน้า
    store.js          // session (JWT), ค่า settings, จำนวนแจ้งเตือน
    api/
      client.js       // fetch + แนบ JWT + จัดการ 401/403
      mock.js         // ข้อมูลจำลองระหว่างรอ API จริง
    utils/
      validate.js     // validation ทุกฟอร์ม (pure function, test ง่าย)
      datetime.js     // แสดงเวลาแบบ UTC+7 ภาษาไทย
      status.js       // map สถานะ -> ข้อความ + สี
    components/       // statusBadge, modal, toast, dataTable,
                      // dateTimeRange, countdown, barcodeInput
    pages/
      auth/           // login, register
      member/         // home, search, notebookDetail, history,
                      // notifications, profile
      admin/          // dashboard, returns, notebooks, models,
                      // brands, loans, reservations, members,
                      // reports, settings, auditLog
  tests/
    unit/
    e2e/
```

## 2. แนวทางดีไซน์

โจทย์คือ "คม ชัด น่าเชื่อถือ" และ "ใช้งานง่ายสำหรับคนไม่เก่งเทคโนโลยี" ส่วนปัญหาหลักที่ระบบต้องแก้คือ **การยืมเกินเวลา**

จุดเด่นจุดเดียวของระบบคือ **"บัตรยืม"** บนหน้าแรกของสมาชิก แสดงเวลาที่เหลือก่อนต้องคืนเป็นตัวเลขขนาดใหญ่ และเปลี่ยนสีตามความเร่งด่วน ส่วนอื่นของระบบเรียบและเป็นระเบียบ ใช้ตารางและรายการธรรมดา ไม่ใช้การ์ดตกแต่ง

หน้าแรกของแอดมินเป็นคิว "รอยืนยันรับคืน" ทันที แทน dashboard การ์ดสถิติ เพราะเป็นงานที่แอดมินทำบ่อยที่สุด

### สี (Design tokens)

| Token | Hex | ใช้กับ |
| --- | --- | --- |
| `--ink` | #14213D | ตัวอักษรหลัก, header, ปุ่มหลัก |
| `--paper` | #F6F8FA | พื้นหลัง |
| `--line` | #D0D7DE | เส้นแบ่ง, ขอบ input |
| `--ok` | #1A7F4B | ว่าง, สภาพปกติ |
| `--busy` | #1F5FBF | ถูกยืม, กำลังยืม |
| `--hold` | #A86B00 | ถูกจอง, ใกล้ครบกำหนด (≤ 60 นาที) |
| `--alert` | #B42318 | เกินกำหนด, เสียหาย, คืนช้า |
| `--muted` | #5B6573 | ซ่อมบำรุง, ปลดระวาง, ยกเลิก, รอยืนยัน |

ป้ายสถานะทุกตัวแสดง **ข้อความกำกับเสมอ** ไม่ใช้สีอย่างเดียว เพื่อรองรับผู้ใช้ที่แยกสีไม่ได้

### ฟอนต์

- **IBM Plex Sans Thai Looped** – เนื้อหาทั้งหมด (อักษรไทยแบบมีหัว อ่านง่ายสำหรับผู้ใช้ทั่วไป)
- **IBM Plex Sans Thai** ตัวหนา – หัวข้อและตัวเลขนับถอยหลัง
- โหลดจาก Google Fonts, fallback เป็น `Tahoma, sans-serif`

### Layout

- Mobile-first เนื้อหาจัดชิดซ้าย
- มือถือ: เมนูอยู่ด้านล่างจอ (สมาชิกมี 4 เมนู)
- เดสก์ท็อป: เมนูย้ายเป็น sidebar ด้านซ้าย
- ปุ่มสูงอย่างน้อย 44px ใช้คำกริยาที่บอกผลชัดเจน เช่น ปุ่ม "คืนเครื่อง" → toast "คืนเครื่องแล้ว รอแอดมินรับเครื่อง"

## 5. แมป Workflow กับ UI และ Validation ฝั่ง frontend

ตามข้อ 10 ของ requirement กฎที่ขึ้นกับเวลาปัจจุบันและการตรวจเวลาทับกันเป็นหน้าที่ของ backend ดังนั้น validation ฝั่ง frontend มีไว้เพื่อ **ช่วยผู้ใช้** เท่านั้น และต้องแสดงข้อความ error จาก backend ให้ผู้ใช้เห็นเสมอ

| Workflow | สิ่งที่ UI ทำ | Validation ฝั่ง frontend |
| --- | --- | --- |
| ยืมทันที | ปุ่ม "ยืม" แสดงเฉพาะเครื่องที่ว่าง, ปิดปุ่มถ้ามีรายการยืมอยู่แล้ว 1 เครื่อง | เวลาคืน > ตอนนี้, ไม่เกิน `max_loan_hours`, เตือนถ้าเลยเวลาที่มีคนจองไว้ |
| ต่อเวลา | แสดงกำหนดคืนเดิมเทียบกับกำหนดคืนใหม่ | กำหนดคืนใหม่ > กำหนดคืนเดิม, รวมแล้วไม่เกิน 24 ชม. นับจากเวลายืม, ไม่เกินกำหนดและยังไม่กดคืน |
| คืน | modal ยืนยันก่อนส่ง | – |
| จองล่วงหน้า | dateTimeRange พร้อมแสดงช่วงที่ถูกจองไว้แล้ว | เริ่ม > ตอนนี้, เริ่มไม่เกิน 7 วันข้างหน้า, สิ้นสุด > เริ่ม, ช่วงยาวไม่เกิน 24 ชม. |
| ยืนยันรับคืน | ต้องเลือกสภาพเครื่องก่อนกดได้, ถ้าเลือก "เสียหาย" บังคับกรอกหมายเหตุ | ต้องเลือกสภาพ |
| สมัครสมาชิก | – | อีเมลถูกรูปแบบ, รหัสผ่าน ≥ 8 ตัว, เบอร์โทร 10 หลักขึ้นต้นด้วย 0, ช่องบังคับครบ **[สมมติฐาน]** |

### รายละเอียดอื่น

- **แจ้งเตือน:** polling ทุก 60 วินาทีเพื่ออัปเดตตัวเลขบนกระดิ่ง (ไม่ใช้ WebSocket) ตัวนับถอยหลังบนบัตรยืมคำนวณฝั่ง client ทุก 30 วินาที
- **Barcode:** เครื่องสแกน USB ทำงานเหมือนคีย์บอร์ด ช่อง `barcodeInput` รับค่าแล้วค้นหาทันทีเมื่อเครื่องสแกนส่ง Enter ไม่ต้องใช้ library
- **เวลา:** แสดงผลด้วย `Intl.DateTimeFormat('th-TH', { timeZone: 'Asia/Bangkok' })` เสมอ ไม่ว่าเครื่องผู้ใช้จะตั้ง timezone แบบไหน
- **สิทธิ์:** router ตรวจ role ก่อนเข้าหน้า สมาชิกที่เข้า `#/admin/*` ถูกพากลับหน้าแรก ถ้าได้ 401 จาก API (token หมดอายุ) พาไปหน้า login

## 6. แผนการทดสอบ UI

เครื่องมือทั้งหมดเป็น dev dependency ใช้ตอนพัฒนาเท่านั้น ไม่ถูกส่งไปกับระบบจริง

| ชั้น | เครื่องมือ | ทดสอบอะไร |
| --- | --- | --- |
| Unit | Vitest | `validate.js`, `datetime.js`, `status.js`, router guard |
| Component | Vitest + jsdom | statusBadge, countdown, modal, barcodeInput |
| E2E | Playwright + mock API | workflow ครบเส้น บนจอเดสก์ท็อปและมือถือ (375px) |
